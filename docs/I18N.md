# I18N: translation dictionary

Languages: **Russian** (default) and **English**. The user switches in "Меню" → Язык / Language.

All UI and document strings live in **`src/i18n/locales/<lang>.js`**: one file per language (`ru.js`, `en.js`). `src/i18n/dict.js` puts them together (`DICT`) and lists the languages (`SUPPORTED_LOCALES`, first = default; `LOCALE_NAMES`, each written in its own language). The provider and hook are in `src/i18n/I18nProvider.jsx`. Outside React (export, utils) use `makeTranslator(locale)` from `src/i18n/translate.js`. It's the same logic.

## Editing a phrase

Open the language file and change **only the text on the right**:

```js
"menu.new": "Новый проект",                     // plain text
"gallery.count": (n) => `${n} фото`,            // a function: inserts a value
```

- The key on the left (`"menu.new"`) is what the code looks for. Don't change it: a wrong key shows up as the raw key in the UI.
- In a function, keep `${…}` and the backticks.
- Every line ends with a comma.
- The prefix says where the text is: `menu.*` the header menu, `appearance.*` theme and font names, `replace.*` the replace dialog, `open.*` opening a file, `editor.*` / `meta.*` / `times.*` / `staff.*` / `plots.*` / `gallery.*` / `fixtures.*` / `cues.*` / `commentary.*` the editor, `doc.*` the document (and the export), `storage.*` / `unit.*` storage messages.

## DICT structure

The dictionary is **flat**: keys are dotted strings, not nested objects. Key prefixes in use: `app`, `menu`, `appearance`, `replace`, `open`, `editor`, `meta`, `times`, `staff`, `plots`, `gallery`, `lightbox`, `fixtures`, `cues`, `ma2`, `md`, `commentary`, `doc`, `export`, `storage`, `drop`, `unit`, `common`.

## API

```jsx
const { t, tn, locale, setLocale } = useT();

t("editor.fixtures")                  // → string (or the key itself if missing)
tn("gallery.count", photos.length)    // → calls the function value with the args
setLocale("en")                       // switch and remember
```

- The choice is saved in localStorage under `tld.locale.v1`, **only when the user picks** a language. Unknown or missing → Russian. The `index.html` head script reads it too (for `<html lang>` before React starts).
- `I18nProvider` sets `<html lang>` (screen readers, hyphenation, spell-check) and the tab title (`app.title`).
- If a key is missing in the active language, `t(key)` returns the key itself. Seeing a raw key in the UI means "not translated".
- If the locale is unknown, `t` falls back to Russian.
- **The export is written in the current language** (and font): `Topbar` calls `exportDocument(project, { locale, font })`. Its `<html lang>` matches.
- **Dates:** `<input type="date">` stores `2026-12-25`; the document shows it with `utils/formatDate.js` (`Intl.DateTimeFormat`, built into the browser, offline): "25 декабря 2026 г.", "December 25, 2026".

## How to add a language

1. Copy `locales/ru.js` to `locales/<lang>.js`, rename the export, translate every value.
2. Import it in `dict.js`, add it to `DICT`, `SUPPORTED_LOCALES` and `LOCALE_NAMES` (the name in that language).
3. Add the code to the language list in the `index.html` head script.
4. `npm test`: `tests/i18n.test.jsx` checks that every language has exactly the Russian keys, of the same kind.

## Rules

1. **All UI strings and document text go through `t()` / `tn()`.** Hardcoded text is not allowed. ESLint enforces it: any Cyrillic string literal outside `src/i18n/dict.js` and `src/i18n/locales/` is an error, as is any text node in JSX.
2. **Plurals and variables use a function value:** `"fixtures.total": (n) => \`Total: ${n} ${n === 1 ? "unit" : "units"}\``. There is no `{n}` placeholder syntax: `tn()` only calls functions, so `"… {n} …"` would show a literal `{n}`.
3. **Dates and numbers:** `Intl` / `toLocaleString(locale)` or a plain string. No moment/dayjs.
4. **No emoji** in the dictionary.
5. **No nested interpolation** (KISS). If you need variables, use a function.
